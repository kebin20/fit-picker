# App audit — v0.10.1

16 November 2026. This review covers the outfit studio, wardrobe editor, recommendations, saved looks, backups, offline use, image failures and optional 3D preview. It fixes the reproducible issues below; it cannot establish that every possible browser/device bug is absent.

## Phone and tablet behavior

The bottom navigation is measured including its border and safe-area padding. Page-end space, scroll padding and notifications use that measured height. This fixes controls scrolling behind the navbar, including when the home-indicator inset grows without changing the navbar's content height.

Dialogs use the visual viewport so their scrollable area can shrink when available screen space changes. Both dialog headers keep a 44-pixel close button accessible; the background and navigation become inert while an overlay is open. Closing restores the previous scroll position and focus. Save look now focuses its name field after the native dialog opens. Changing pages resets scroll to the heading instead of carrying a deep wardrobe scroll into the studio.

Long garment/saved-look names wrap, very narrow wardrobes use one column, phone save previews use two columns, and active tablet/sidebar navigation keeps white text/icons on its dark background when hovered.

## Functional fixes

- Editing a saved look into an already-saved combination merges duplicates while retaining the edited look's ID.
- Restoring a backup clears stale editing, deleted-look and selection-undo state. Failed restore/delete undo writes retain the recovery action so it can be retried. Malformed backups reject impossible clothing slots, repeated physical garments, duplicate IDs, wrong optional-field types and invalid dates before replacing local data. Known unowned archive pieces remain valid for repairing older saved looks.
- Repeated “Wore this today” actions compare actual clothing slots, independent of JSON property order.
- Photo uploads use a selection revision: a slow earlier image cannot replace a newer image or reappear after removal. Saving waits for image processing.
- Garment and saved-look storage errors appear inside the active dialog, so the message is visible above the overlay.
- Failed garment, portrait and guide images retry after reconnecting or changing their source. Existing garment compositions remain the portrait fallback.
- Recommendations require confirmed, season-appropriate pieces in valid slots and cannot use the same physical garment twice.
- Offline releases cache valid entry JavaScript/CSS before replacing cached HTML. Interrupted downloads or HTML masquerading as a missing asset preserve the previous bootable shell. URL-only cache lookup also fixes misses caused by `Vary: Origin` and crossorigin module requests.

## Performance

Recent-wear counts are calculated once before sorting recommendations. The development-machine fixture with 133 looks and 2,000 history entries changed from approximately 177 ms to 1.4 ms with identical ordering. This is a local CPU fixture, not a physical-iPhone timing claim. Reproduce with `node scripts/measure-outfit-ranking.mjs`.

The 3D renderer now reapplies its phone pixel/shadow limits after resizing, including a landscape touch phone or tablet split view. Replaced shadow maps are disposed. The default remains 2D, with 3D, decoder, model portraits and source originals deferred. A settled 3D preview produced zero additional renders during the one-second observation. No runtime dependency was added.

See the [resource measurements and further optimization options](performance-audit-2026-11-16.md). Priorities for a later update are profiling an older physical iPhone, evaluating local font subsets, and adding controls to inspect/prune optional offline downloads. Further model simplification should be checked visually against the garment realism required here.

## Verification

- 66 unit tests and the TypeScript/Vite production build.
- Complete browser flow: all clothing slots, outerwear, 3D controls, local save/reload/delete, search, source links, seasons/occasions, ownership, recommendations, undo, mobile navigation and image/WebGL/model/decoder failure fallbacks.
- Personal flow: locks, laundry, weather filters, draft/history persistence, editor photos, backup rejection/restore and a real offline reload of saved garment images.
- Isolated functional regressions: keyboard focus/Tab/Escape/scroll restoration, saved-look merging, backup transitions, history deduplication, storage failures and overlapping photo uploads.
- Real service-worker fixture: interrupted new entry script, SPA fallback MIME mismatch, successful update and subsequent offline reload, preserving saved garment images without caching the full 3D or portrait library.
- 3D quality switches between tablet, portrait phone, landscape touch phone and tablet again, with no idle render loop.
- 22 Chromium/WebKit layout scenarios: 320/375/390/430-pixel phones; 768/820/1024-pixel tablets; 844×390 landscape; 390×320 reduced-height screen; synthetic top/bottom home-indicator and landscape side insets. Assertions check document/dialog overflow, full button clearance and actual hit testing, last wardrobe/picker actions, saved-look actions, filters and reachable dialog controls.

The 22 layout scenarios, personal/offline flow and nine isolated functional browser cases also passed against that deployment.
